# Complete results and report delivery

Search exact UPN/object ID first, then display name plus secondary attributes. Inspect filters, preserve requested scope and remove only conflicting stale filters. Use server-side search/filtering before paging.

For complete lists/reports, prefer a full filtered export. Verify tenant, filters/period, result/export count and required columns. Visible pages or selected rows may be incomplete. For paginated/virtualized lists track unique IDs and boundaries; repeated IDs without progress mean a paging problem, not exhaustion. Mark unverified completeness as partial.

## Outlook report delivery

Send reports through Outlook on the web in the same active authenticated Chrome profile on Windows and macOS. Reuse an existing Outlook tab first. If none exists, use a live Outlook/app-launcher link in that profile and preserve the tenant's cloud, including sovereign-cloud destinations. Do not silently substitute the admin portal's **Email** action, Gmail, native Outlook, AppleScript, COM, or another browser/profile. Do not hardcode a mailbox, local username, account, or download path.

An explicit send request authorizes one message with the established report scope and exact recipient. A request to prepare or review a report alone does not authorize sending. Carry matching authorization across report creation and navigation; do not add a second skill-imposed confirmation before Send. Ask only for a missing material choice or follow a tool-required approval. Do not add unrequested recipients, CC/BCC, recurring delivery, or scheduling.

1. Verify the signed-in employee's Outlook mailbox and the message's **From** address before Send. The administrator identity used to collect tenant data can differ from the employee's sending mailbox; do not assume they are the same or switch senders without authorization. Use the exact recipient from the request. Resolve “me” only from established requester identity and a verified address; if that identity is ambiguous, ask for the address. Never infer the owner's personal address from a local account, skill author, or unrelated tenant/contact record.
2. Prepare the complete requested report and open Outlook's **New mail** / **New message** or the current equivalent. A short, complete inventory can go in the message body when no file was requested. Identify its tenant, scope, filters/period and completeness; do not present visible rows as the full inventory. If a file or format was requested, supply that artifact rather than replacing it with a body summary.
3. For an attachment, use an actual supported report export/download and Outlook upload workflow. Read the current tool's download and file-upload documentation before using those capabilities. Use the returned or otherwise verified file reference/path; never invent a path or claim that a download is an attachment. Verify the downloaded filename, nonempty requested content/format, export completeness and size where supported metadata exposes it. In the composer, use **Attach file → Browse this computer** or the observed current equivalent with the supported upload capability. Wait until Outlook shows a completed attachment with the matching filename, not an upload still in progress or an error. Compare its size when available; a filename-only Outlook attachment display does not block a file verified through the actual download/upload workflow.
4. Inspect the final **From**, exact **To**, absence of unrequested CC/BCC, subject, report body, scope/period and completed attachments. Send once under the matching explicit authorization. If submission is uncertain, inspect **Sent Items** before taking any further action; never resend to resolve uncertainty.
5. Verify the message in **Sent Items**, matching sender, recipient, subject, report content/attachments and send time. A success toast alone is insufficient. Report a verified sent/accepted message separately from confirmed recipient delivery; do not claim receipt without delivery evidence. If Sent Items cannot establish the result, report the send as unverified and do not duplicate it.

If a required capability is unavailable, finish the independent report work and state the precise blocker. For a short body report, missing download/upload capability is not a blocker. If a requested attachment cannot be downloaded, inspected or uploaded with the available supported tools, retain the report and ask only for the missing capability or necessary user step; do not invent an attachment or switch delivery applications. Expired Outlook authentication follows the shared browser contract's human-restoration checkpoint.

Microsoft's [compose guidance](https://support.microsoft.com/en-us/outlook/create-and-respond-to-messages-in-outlook-web-app) and [attachment guidance](https://support.microsoft.com/en-us/outlook/mail/add-pictures-or-attach-files-to-emails-in-outlook) describe the mail workflow; follow the live UI and current tool documentation for execution.

## Retained evidence

Retain tenant/target, relevant before/after evidence, changes, already-correct items, affected workloads and pending work. Specialist reporting lists define retained evidence, not mandatory spoken narration. Expand into a detailed report only when requested; never include secrets or temporary credentials.
